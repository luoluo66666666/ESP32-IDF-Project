## 〇、测试环境与密码

### 0.1 环境性质说明

| 环境 | 说明 |
|------|------|
| **AP 配网 TCP** | 设备出厂配网能力，`192.168.4.1:9000` 为设备固定能力，**非测试专用** |
| **云端 TCP** | 文档中的 `192.168.1.125:9000` 等为 **当前局域网联调测试地址**，由开发电脑或桥接程序监听 |

## 重要说明（请先读）

本设备固件采用 **「发什么回什么」的明文行协议**，三通道命令完全一致：

| 通道 | 用途 |
|------|------|
| **AP 本地 TCP** | 首次配网、未连路由器时 |
| **BLE 蓝牙** | 配网 / 调试（与 TCP 同命令） |
| **STA 云端 TCP** | 正常工作阶段，设备主动连接服务器 |

**上位机必须按本文协议实现，不要按 WebSocket/UDP JSON 方案对接。**

- 无 `CMD|` / `ACK|` 外层包装  
- 无 `{"type":"online"}` 等 JSON 报文  
- 一行一条命令，建议以 `\n` 结尾  
- 应答为明文文本，常见以 `\r\n` 结尾

## 一、整体架构（上位机视角）

```
┌──────────────┐   WiFi 连热点 ESP-WASH          ┌─────────────────┐
│  小程序/App   │──TCP 192.168.4.1:9000────────►│   洗头机硬件     │
│  (配网阶段)   │   发 CFG:/SYS: 明文命令         │   (AP 配网模式)  │
└──────────────┘                                  └────────┬────────┘
                                                           │
┌──────────────┐   BLE 同协议（可选）                      │ CFG:APPLY 后
│  小程序/App   │────────────────────────────────────────►│ 连店铺 WiFi
└──────────────┘                                          │
                                                           │ TCP 客户端
                                                           │ 主动连接
                                                           ▼
                                                  ┌─────────────────┐
                                                  │ 云端 TCP 服务器   │
                                                  │ 【当前为测试环境】 │
                                                  │ 例: x.x.x.x:9000  │
                                                  └─────────────────┘
                                                           ▲
┌──────────────┐   TCP 同协议发 CMD:MODE* 等               │
│ 网页/后台/App │──────────────────────────────────────────┘
└──────────────┘
```

**上位机需要实现两部分：**

| 阶段 | 协议 | 角色 | 说明 |
|------|------|------|------|
| 配网阶段 | TCP | **客户端**连 `192.168.4.1:9000` | 热点密码 `12345678`；下发 WiFi、**测试/生产**云端地址 |
| 工作阶段 | TCP | **服务端**监听 `SERVER_PORT` | 设备连上来后发 `REG\|...`；**当前联调多为测试机 9000 端口** |

## 二、设备固化参数

### 2.1 设备侧固定（不随环境变）

| 参数 | 值 | 备注 |
|------|------|------|
| 配网热点 SSID | `ESP-WASH` | 固定，与店铺 WiFi 无关 |
| **配网热点密码** | **`12345678`** | 固定，8 位数字 |
| AP 本地 TCP | `192.168.4.1:9000` | 仅 AP 配网模式；**无连接密码** |
| WiFi 频段 | 2.4GHz only | ESP32 不支持 5GHz |
| 设备 ID 格式 | `SN_` + MAC 六字节十六进制 | 如 `SN_98A316ECF194` |
| 配置存储 | Flash NVS 分区 `device_nvs` | 断电不丢失 |
| WiFi 试连超时 | **30 秒** | 失败回滚并退回 AP |
| TCP 断线重连 | 约 **1～2 秒** 后重连 | 设备侧自动，非指数退避 |
| 单条报文最大长度 | **256 字节** | 含命令与应答 |
| DI 监测周期 | **100 ms** | 后台任务 `di_input_monitor_task` |
| 水温监测周期 | **1 s** | 后台任务 `temp_monitor_task` |
| 默认目标水温 | **39 ℃** | 容差 **±5 ℃**（34～44 ℃ 为就绪） |

### 2.2 固件后台任务（当前 V1.5）

上位机**无需**也**无法**直接控制这些任务；了解其行为有助于解析推送与洗涤节奏。

| 任务名 | 创建位置 | 职责 |
|--------|----------|------|
| `di_input_monitor_task` | `main.c` | 100ms 采样 DI → 写缓存；按配置处理**报警推送** / **暂停关 DO** |
| `temp_monitor_task` | `main.c` | 1s 读 Modbus 水温 → 写缓存；未达标时 **TCP 推送** `TEMP,ERR,...` |
| `mode_control_task` | `main.c` | 等待 `CMD:MODE*` 事件，执行洗涤状态机 |
| `wifi_protocol_task` / `tcp_client` | `wifi_tcp_start()` | 云端 TCP 收发，命令进 `ctrl_protocol()` |

**原则：** 洗涤程序**不直接读 GPIO/Modbus**，只读监测任务缓存（`CMD:DI_GET` 同理）。

### 2.3 固件编译默认值（可被 CFG 覆盖，当前测试常用）

| 参数 | 默认值 | 备注 |
|------|--------|------|
| 店铺 WiFi SSID | `ZMJD` | 仅未配网前的编译默认，**联调请用 `CFG:WIFI_SSID` 填写真实路由器** |
| **店铺 WiFi 密码** | **`ZM888888`** | 同上 |
| **测试云端 TCP** | **`192.168.1.125:9000`** | ⚠️ **仅局域网测试**；生产地址另配 |

## 三、传输层约定

### 3.1 帧格式

- **编码**：UTF-8 兼容 ASCII（中文 SSID 支持 UTF-8）
- **分帧**：以 `\n` 作为一条命令/应答的结束符；`\r` 会被忽略
- **请求-响应**：发一条命令，设备处理完后回一条应答（同步语义）
- **无会话 ID**：不依赖 `requestId`，命令本身即语义

### 3.2 示例（配网）

```text
上位机发送 → CFG:WIFI_SSID=店铺WiFi\n
设备回复   ← CFG:OK,WIFI_SSID\r\n

上位机发送 → CFG:APPLY\n
设备回复   ← CFG:OK,APPLY\r\n
```

### 3.3 设备主动推送（非命令应答）

| 场景 | 设备发出 | 上位机处理 |
|------|----------|------------|
| AP 本地 TCP 客户端连上 | `CMD:SN,OK,SN=SN_XXXX` | 解析设备 ID，可主动发 `CMD:SN_GET` 再确认 |
| BLE 开启 Notify 后 | `CMD:SN,OK,SN=SN_XXXX` | 同上 |
| STA 云端 TCP 连上/重连 | `REG\|SN_XXXX\|固件版本` | 登记在线设备，可回 `REG,OK`（设备会忽略） |
| 任一路 DI 电平变化 | `DI,DI0=1` / `DI,DI2=0` … | 统一推送 **0/1**；报警/暂停等业务含义由**上位机**配置表判断 |
| 水温未达标 / 读失败 | `TEMP,ERR,NOT_READY,...` 或 `TEMP,ERR,READ_FAIL` | 全程监测推送；出水步会**阻塞**直至就绪 |

> **说明：** 设备只报 DI 电平变化，不区分报警/暂停语义。固件内部仍按 `di_role_config[]` 处理暂停关 DO 等；上位机收到 `DI,DI2=1` 可自行映射为「暂停按下」。

## 四、AP 配网阶段（TCP 客户端连设备）

### 4.1 何时进入配网模式

| 条件 | 设备行为 |
|------|----------|
| 首次上电，NVS 无 `wifi_prov` | 开热点 `ESP-WASH`，监听 `192.168.4.1:9000` |
| 配网试连 WiFi 30s 失败 | 回滚配置，重新开 AP |
| 收到 `SYS:MODE=AP` | 清除已配网标志，退回 AP |

### 4.2 上位机配网步骤

```
1. 手机/电脑连接 WiFi：ESP-WASH，密码：12345678
2. TCP connect → 192.168.4.1:9000（无需 TCP 用户名密码）
3. 收到设备推送：CMD:SN,OK,SN=SN_98A316ECF194
4. 依次发送 CFG 命令（见第五节）
5. 发送 CFG:APPLY（或 SYS:MODE=STA）
6. 设备关 AP，连店铺 WiFi，再连云端 TCP
7. 上位机在云端 TCP 服务器上等待 REG|SN_...|版本
```

### 4.3 配网时序图

```
小程序/配网工具                    洗头机(AP 模式)
    │                                    │
    │── TCP connect 192.168.4.1:9000 ──►│
    │                                    │
    │◄── CMD:SN,OK,SN=SN_XXXX ───────────│  连接后主动推送
    │                                    │
    │── CFG:WIFI_SSID=店铺WiFi ─────────►│
    │◄── CFG:OK,WIFI_SSID ───────────────│
    │                                    │
    │── CFG:WIFI_PASSWORD=密码 ──────────►│
    │◄── CFG:OK,WIFI_PASSWORD ───────────│
    │                                    │
    │── CFG:SERVER_IP=192.168.1.125 ───►│
    │◄── CFG:OK,SERVER_IP ───────────────│
    │                                    │
    │── CFG:SERVER_PORT=9000 ───────────►│
    │◄── CFG:OK,SERVER_PORT ─────────────│
    │                                    │
    │                                    │
    │── CFG:APPLY ─────────────────────►│
    │◄── CFG:OK,APPLY ───────────────────│  表示开始切 STA
    │                                    │
    │  (AP 热点断开，TCP 连接会断开)        │
    │                                    │── 连店铺 WiFi ──►
    │                                    │── TCP 连云端服务器 ──►
    │                                    │── REG|SN_xxx|版本 ──► 云端
```

> **注意**：`CFG:OK,APPLY` 只表示「参数已接收并开始切网」，不代表 WiFi 已连上。配网是否成功，应以云端收到 `REG|...` 为准；失败时约 30s 后设备会重新出现 `ESP-WASH` 热点。

### 4.4 配网失败判断

| 现象 | 上位机处理建议 |
|------|----------------|
| 30s 内云端无 `REG\|...` | 提示用户检查 WiFi 密码/信号 |
| 再次出现热点 `ESP-WASH` | 试连失败已回滚，需重新配网 |
| `CFG:ERR,*` | 参数非法，见第五节完整命令手册 |

## 五、完整命令手册（上位机发送 → 设备功能 → 应答示例）

> **阅读方式**：每一条均给出「发送什么」「干什么」「成功/失败回什么」。  
> **通道**：AP 本地 TCP、BLE、STA 云端 TCP **完全相同**（设备主动推送除外，见 5.0）。  
> **格式**：建议每条命令以 `\n` 结尾；下文示例中 `\n` 省略不写。

### 5.0 设备主动推送（非上位机发送）

#### 5.0.1 AP 本地 TCP / BLE 连上后推送设备码

**触发**：手机 TCP 连上 `192.168.4.1:9000`；或 BLE 开启 Notify 后。

**设备发出示例：**

```text
CMD:SN,OK,SN=SN_98A316ECF194
```

**含义**：告知当前设备唯一 ID，格式 `SN_` + WiFi MAC 十二位十六进制。

---

#### 5.0.2 云端 TCP 连上/重连后注册

**触发**：设备 STA 模式下 TCP `connect` 测试/生产服务器成功。

**设备发出示例：**

```text
REG|SN_98A316ECF194|1.0.0
```

**含义**：设备上线登记；第三段为固件版本号。

**上位机可选回复（设备会忽略）：**

```text
REG,OK
```

---

#### 5.0.3 DI 状态主动上报（仅云端 TCP）

**触发**：DI0～DI5 任一路电平变化（0↔1），且云端 TCP 已连接。

**设备发出示例：**

```text
DI,DI1=1
DI,DI1=0
DI,DI2=1
DI,DI2=0
```

**格式**：`DI,DIx=n`，`x` 为通道号 0～5，`n` 为 `0` 或 `1`。

**上位机处理**：

- 设备**不**在推送里区分报警/暂停/普通
- 上位机维护业务映射表，自行解释，例如：
  - `DI,DI0=1` → 报警 A 触发
  - `DI,DI2=1` → 暂停键按下
  - `DI,DI4=1` → 水位开关有效

**设备侧行为（与推送无关）**：固件仍按 `di_role_config[]` 本地处理——报警不停洗、暂停键关 DO 等。

---

#### 5.0.4 水温异常主动上报（仅云端 TCP）

**触发**：`temp_monitor_task` 检测到水温不在允许范围，或 Modbus 读失败。

**设备发出示例：**

```text
TEMP,ERR,NOT_READY,CUR=32,TARGET=39,MIN=34,MAX=44
TEMP,ERR,READ_FAIL
```

**含义：**

- `NOT_READY`：当前水温不在 `[TARGET±5℃]`（默认目标 39℃）
- 状态变化时推送；未达标时每 **5 s** 可重复提醒
- `CMD:MODE0` 洗涤时，**出水相关步骤**会阻塞，直至缓存显示水温就绪

### 5.2 SYS 系统命令

---

#### `SYS:STATUS` — 查询设备运行状态

### 5.5 DI 数字输入（报警 / 暂停 / 查询）

设备有 **6 路数字输入 DI0～DI5**。固件在 `mode_ctrl.c` 的 **`di_role_config[]`** 中为每路配置角色（**上位机不可改**，需固件侧调整）：

| 配置值 | 角色 | 行为 |
|--------|------|------|
| `0` | 普通 | 仅更新缓存，不推送、不暂停 |
| `1` | **报警** | 设备侧**不停止**洗涤；推送仍为 `DI,DIx=0\|1` |
| `2` | **暂停** | 按住 **DO 全关**、洗涤**计时暂停**；推送仍为 `DI,DIx=0\|1` |

**当前固件默认配置（V1.5）：**

| DI | 角色 | 说明 |
|----|------|------|
| DI0 | 报警 (`1`) | 设备侧不暂停洗涤 |
| DI1 | 报警 (`1`) | 同上 |
| **DI2** | **暂停 (`2`)** | 面板暂停键；按住关 DO、流程暂停 |
| DI3 | 报警 (`1`) | 硬件可为流量脉冲，角色以固件表为准 |
| DI4 | 普通 (`0`) | — |
| DI5 | 普通 (`0`) | — |

#### 5.5.1 硬件引脚映射

| 软件下标 | 板级 | GPIO | 典型用途 |
|----------|------|------|----------|
| DI0 | MCU_DI_0 | GPIO4 | 报警输入 |
| DI1 | MCU_DI_1 | GPIO5 | 报警输入 |
| DI2 | MCU_DI_2 | GPIO6 | **暂停键**（默认） |
| DI3 | MCU_DI_3 | GPIO7 | 流量脉冲 / 可配报警 |
| DI4 | MCU_DI_4 | GPIO15 | 水位等开关量 |
| DI5 | MCU_DI_5 | GPIO16 | 通用数字输入 |

**电气约定：** 内部上拉；**高电平 = 1 = 有效**；监测任务内连续 3 次采样为高才确认。

#### 5.5.2 TCP 主动推送（统一格式）

**触发：** DI0～DI5 任一路电平变化，且云端 TCP 已连接。

```text
DI,DI0=1
DI,DI0=0
DI,DI2=1
DI,DI2=0
```

每路变化各推一行。上位机根据自有配置判断 DI0=1 是报警、DI2=1 是暂停等。

也可轮询 `CMD:DI_GET` 读取 6 路当前电平。

#### 5.5.3 设备侧本地行为（默认配置参考）

以下为固件 `di_role_config[]` 的**设备内部**逻辑，**不体现在推送格式里**：

| 角色 | 设备行为（本地） |
|------|------------------|
| 报警 DI0/DI1/DI3 | 洗涤**不停止** |
| 暂停 DI2 | 按下关 DO、计时暂停；松开恢复 |

> 无 TCP 暂停命令；不能远程发令暂停，只能读推送或 `CMD:DI_GET`。

#### 5.5.4 查询命令

| 命令 | 功能 | 应答示例 |
|------|------|----------|
| `CMD:DI_GET` | 6 路电平 + 报警汇总 | `CMD:DI_GET,OK,DI0=0,DI1=1,...,ALARM=1,ERR=DI,ERR,DI1` |
| `CMD:MODE_GET` | 模式 + 报警 | `CMD:MODE_GET,OK,MODE=0,RUN=1,ALARM=1,ERR=DI,ERR,DI1` |

`CMD:MODE*` 启动洗涤**不受** DI 报警影响；报警与暂停均**不替代** `CMD:STOP`。

#### 5.5.5 对话示例

**例 1：DI1 变高（上位机映射为报警）**

```text
← 设备推送    DI,DI1=1
```

**例 2：DI2 暂停键**

```text
→ CMD:MODE0
← CMD:MODE0,OK
← 设备推送    DI,DI2=1
（上位机判为暂停；设备关 DO、洗涤暂停）
→ CMD:DI_GET
← CMD:DI_GET,OK,DI0=0,DI1=0,DI2=1,DI3=0,DI4=0,DI5=0,RAW=0x04,ALARM=0
← 设备推送    DI,DI2=0
（上位机判为恢复；设备继续洗涤）
```

**例 3：报警存在时仍可启动**

```text
→ CMD:MODE0
← CMD:MODE0,OK
（若 DI1 刚变高，可能收到 ← DI,DI1=1）
```

#### 5.5.6 水温全程监测（与 DI 独立）

| 项目 | 说明 |
|------|------|
| 默认目标 | 39℃；就绪区间 **34～44℃**（±5℃） |
| 缓存接口 | `temp_get_water_ready()` — 洗涤程序只读缓存 |
| 未达标推送 | `TEMP,ERR,NOT_READY,CUR=..,TARGET=..,MIN=..,MAX=..` |
| 读失败推送 | `TEMP,ERR,READ_FAIL` |
| 重复提醒 | 未达标时每约 **5s** 可再推（状态变化必推） |

**`CMD:MODE0`（mode4_zhongyao_v2）门控规则：**

- 需水温的步骤：status **0**（放水）及 **1～67 的奇数步**（出水/加液）
- 未就绪：关水路相关输出，**本步计时不增加**；就绪后 `time_cnt` 归零重入该步
- 偶数步为流程内暂停，**不检查**水温

主动查询仍可用 `temp water` / `temp all`（见 **5.9**），与后台监测并行。

```text
→ 上位机发送  CFG:WIFI_SSID=ZMJD
← 设备应答    CFG:OK,WIFI_SSID
→ 上位机发送  CFG:WIFI_PASSWORD=ZM888888
← 设备应答    CFG:OK,WIFI_PASSWORD
→ 上位机发送  CFG:SERVER_IP=192.168.1.125
← 设备应答    CFG:OK,SERVER_IP
→ 上位机发送  CFG:SERVER_PORT=9000
← 设备应答    CFG:OK,SERVER_PORT
→ 上位机发送  CFG:APPLY
← 设备应答    CFG:OK,APPLY
```

**步骤 4：云端 TCP 上线（测试服务器 `192.168.1.125:9000`）**

```text
← 设备推送    REG|SN_98A316ECF194|1.0.0
→ 上位机可选  REG,OK
```

**步骤 5：业务控制**

```text
→ 上位机发送  CMD:MODE_GET
← 设备应答    CMD:MODE_GET,OK
→ 上位机发送  CMD:MODE0
← 设备应答    CMD:MODE0,OK
→ 上位机发送  CMD:STOP
← 设备应答    CMD:STOP,OK
```

**步骤 6：DI 状态主动上报**

```text
（DI1 变高，云端 TCP 已连接）
← 设备推送    DI,DI1=1
（上位机按配置判为报警；洗涤不停止）
```

**步骤 7：水温未达标推送（MODE0 出水步阻塞）**

```text
（CMD:MODE0 运行中，水温低于 34℃）
← 设备推送    TEMP,ERR,NOT_READY,CUR=32,TARGET=39,MIN=34,MAX=44
（水温恢复后洗涤继续，可能不再重复推送直至下次异常）
```

**步骤 8：DI2 变高/变低**

```text
← 设备推送    DI,DI2=1
→ CMD:DI_GET
← CMD:DI_GET,OK,...,DI2=1,...,ALARM=0
← 设备推送    DI,DI2=0
```

## 六、STA 工作阶段（云端 TCP）

### 6.1 连接模型

| 项目 | 说明 |
|------|------|
| 连接方向 | **设备作为 TCP 客户端**，主动 `connect` 上位机 |
| 服务器地址 | 配网时写入的 `SERVER_IP` + `SERVER_PORT` |
| **当前测试地址** | **`192.168.1.125:9000`**（开发机局域网 IP + 桥接监听，**非生产**） |
| **生产地址** | 由部署方提供后通过 `CFG:SERVER_IP` / `CFG:SERVER_PORT` 配置 |
| TCP 鉴权 | **无**用户名密码 |
| 心跳 | **设备不主动发心跳**；上位机可发 `PING`，设备忽略不应答 |

### 6.2 断线重连

| 场景 | 设备行为 |
|------|----------|
| TCP 断开 | 约 1s 后重连同一 `SERVER_IP:PORT` |
| connect 失败 | 约 2s 后重试 |
| 修改服务器并 `CFG:APPLY` | 断开旧连接，连新地址 |
| WiFi 断开 | 自动重连 WiFi，恢复后再连 TCP |
| 重连成功 | 再次发送 `REG\|SN\|版本`（见 5.0.2） |

> **重要**：TCP 断开**不会**停止正在运行的洗涤模式；须发 `CMD:STOP` 才能停。

## 十、云端 TCP 服务器实现要点

### 10.1 最小实现

```
1. listen(SERVER_IP, SERVER_PORT)   // 通常 0.0.0.0:9000
2. accept() 等待设备连接
3. read 一行 → 收到 REG|SN_xxx|version → 设备上线
4. 维护 sn → socket 映射表
5. 需要控制时：向对应 socket write "CMD:MODE0\n"
6. read 一行 ← 收到 CMD:MODE0,OK
7. 同时监听设备主动推送：DI,DIx=0|1 / TEMP,ERR,...（非命令应答）
8. 连接断开 → 从映射表移除；设备会自动重连并再次 REG
```

### 10.2 多客户端场景

- 同一 SN 重连时，旧 socket 可能先断开再建新连接（复位/重连常见）  
- 应以**最新活跃 socket** 为准发命令  
- 不要要求「手机 App 必须在线」才能控设备（设备与 App 均可直连服务器）

### 10.3 经桥接转发（可选）

若使用 `ESP-wash-app` 桥接服务（`npm run bridge -- --host 0.0.0.0 --port 9000`）：

| 方向 | 格式 |
|------|------|
| 设备 → 桥接 | `REG\|SN\|版本` |
| 桥接 → 设备 | 原样转发 `CMD:MODE0` 等明文 |
| 设备 → 桥接 | `CMD:MODE0,OK` 等应答 |
| 网页/App → 桥接 | 按桥接项目文档（可能与设备明文不同，由桥接转换） |

**设备侧只认第五节所列明文协议。**

## 十一、完整工作流程

### 11.1 首次上电

```
1. 设备上电
2. 读 NVS：wifi_prov == 0 ?
   ├── 是 → 开 AP「ESP-WASH」+ 本地 TCP 9000，等待配网
   └── 否 → 直接 STA，连上次 WiFi + 云端 TCP
3. STA 拿到 IP → 写 NVS wifi_prov=1
4. TCP 连上云端 → 发 REG|SN|版本
```

### 11.2 正常工作循环

```
┌─────────────────────────────────────┐
│     STA + 云端 TCP 已连接            │
├─────────────────────────────────────┤
│  上位机发 CMD:MODE* / CMD:STOP      │
│  设备回 CMD:MODEx,OK 或 CMD:STOP,OK │
│                                     │
│  TCP 断开 → 设备约 1s 后自动重连     │
│  重连后再次 REG|SN|版本              │
│                                     │
│  洗涤运行中 TCP 断开 → 模式继续运行  │
│  DI 变化 → 推送 DI,DIx=0|1           │
│  水温异常 → TEMP,ERR                 │
└─────────────────────────────────────┘
```

### 11.3 远程改配置（已配网设备）

设备在线时可直接通过**云端 TCP** 发送（无需再连 AP）：

```text
CFG:WIFI_SSID=新SSID
CFG:WIFI_PASSWORD=新密码
CFG:APPLY
```

或只改云端地址：

```text
CFG:SERVER_IP=新IP
CFG:SERVER_PORT=9000
CFG:APPLY
```

## 十四、常见问题 FAQ

| 问题 | 解答 |
|------|------|
| 能用 WebSocket / UDP 配网吗？ | **不能**，本固件仅支持本文 TCP 明文协议 |
| 配网热点密码是多少？ | **`12345678`**（SSID：`ESP-WASH`） |
| `192.168.1.125:9000` 是生产地址吗？ | **不是**，仅为当前**局域网测试**；生产地址另配 |
| TCP 连接要账号密码吗？ | **不要**；配网热点 WiFi 需要密码 `12345678` |
| `CFG:WIFI_SSID` 填什么？ | 填**店铺路由器**名称，不是 `ESP-WASH` |
| 测试默认店铺 WiFi 密码？ | 固件默认 **`ZM888888`**（SSID `ZMJD`），实际以配网命令为准 |
| `CFG:OK,APPLY` 后 AP 断了是否正常？ | 正常，设备正在切 STA |
| 怎么判断配网成功？ | 云端 TCP 收到 `REG\|SN\|版本` |
| 设备显示在线但发令无响应？ | 检查是否发到当前活跃 socket；复位后旧连接可能已失效 |
| TCP 断了洗涤会停吗？ | **不会**，需发 `CMD:STOP` |
| 需要 JSON 吗？ | **不需要**，全部明文行 |
| 需要心跳吗？ | 设备不主动心跳；可依赖 TCP keepalive 或业务轮询 `SYS:STATUS` |
| DI 推送什么格式？ | 统一 `DI,DIx=0` 或 `DI,DIx=1`；业务含义上位机自定 |
| DI 报警会停洗涤吗？ | **不会**（设备侧）；上位机收到 `DI,DI1=1` 可自行弹窗 |
| DI2 是报警还是暂停？ | 设备默认 **暂停**；推送仍是 `DI,DI2=1/0`，由上位机映射 |
| 能 TCP 暂停洗涤吗？ | **无**暂停命令；用面板 DI2 或 `CMD:STOP` |
| 水温不够会怎样？ | 推送 `TEMP,ERR,...`；`CMD:MODE0` 出水步阻塞直至就绪 |
| `CMD:DI_GET` 是实时读 GPIO 吗？ | **否**，读监测任务缓存（约 100ms） |
| 用自己电脑当 TCP 服务器？ | 可以：`CFG:SERVER_IP` 填电脑局域网 IP，`npm run bridge` 监听 9000 |
| 与 `WM_` 开头 deviceId 文档冲突？ | 以本固件为准，设备 ID 为 **`SN_` + MAC** |

## 十六、与第三方 JSON/WebSocket 方案差异说明

若其它文档要求 `UDP 8888`、`wss://.../ws/device`、`{"type":"online"}` 等，**与本固件不兼容**。上位机应择一：

| 方案 | 说明 |
|------|------|
| **A（推荐）** | 完全按本文实现 TCP 明文对接 |
| B | 由网关/桥接服务做协议转换（JSON/WS ↔ 本文明文） |

本固件**不提供**协议转换层，转换由上位机或中间服务完成。
